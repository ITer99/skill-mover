# skill搬运工

`skill搬运工` 是一款运行在 Windows 上的文件或文件夹一对多分发工具。

![skill搬运工图标](icon-preview-new.png)

它最初用于解决一个很具体的问题：编写好一个 Skill 后，需要把它分别安装到多个 AI 智能体的 Skill 目录中。现在它也可以用于普通文件、项目资料、配置模板和其他文件夹的批量分发。

一句话概括：

> 选择一个源文件或源文件夹，一次复制到多个本地目录、移动硬盘目录或网络共享目录。

## 适用场景

### Skill 批量安装

将编写好的 Skill 文件夹同时分发到多个智能体，例如：

- Codex Skills 目录；
- Claude Skills 目录；
- 其他 Agent 或自动化工具的扩展目录；
- 不同项目各自维护的本地 Skills 目录。

只需要维护一份 Skill 源文件，更新后点击一次“开始搬运”，即可同步到所有已添加的目标位置。

### 普通文件夹分发

程序不限制源文件夹的内容，可以用于：

- 项目模板分发；
- 配置文件同步；
- 文档和素材批量复制；
- 脚本、插件和工具包部署；
- 本地多个目录之间的资料同步；
- 将同一份内容复制到多个移动硬盘或备份目录。

### SMB 多终端分发

如果多台 Windows、Linux、NAS 或其他终端已经配置好 SMB 文件共享，可以把对应的共享目录添加为目标路径，例如：

```text
\\192.168.1.21\AgentSkills
\\192.168.1.22\SharedFiles
\\NAS\TeamResources
```

也可以先将共享目录映射为 Windows 网络驱动器，再添加盘符路径：

```text
Y:\AgentSkills
Z:\SharedFiles
```

这样便可以从当前电脑一次向多台终端分发文件。

> `skill搬运工` 不负责创建 SMB 服务、网络发现或账号授权。使用前需要确保共享目录已经可以在 Windows 文件资源管理器中正常访问，并且当前用户拥有写入权限。

## 主要功能

- 选择一个源文件或源文件夹，默认使用“文件夹”模式；
- 在“文件”模式下，向多个目标直接分发单个文件；
- 添加任意数量的目标文件夹；
- 使用 Windows 资源管理器风格的现代目录选择器，方便切换盘符、网络位置和 SMB 映射盘；
- 完整复制源文件夹及其全部子目录；
- 一次向多个本地或网络位置分发；
- 自动记住目标路径，关闭程序后不会丢失；
- 显示当前文件和整体搬运进度；
- 自动忽略重复添加的目标路径；
- 文件夹分发时自动排除 `.git`、`.svn`、`.hg`、`node_modules`、`__pycache__` 等开发元数据和缓存目录；
- 个别文件无法读取或写入时记录并跳过，不再让整个分发任务立即中断；
- 阻止复制到源文件夹自身或源文件夹内部；
- 使用 Windows 原生界面，启动快速；
- 独立 EXE，目标电脑无需安装 Python。

## 使用方法

1. 前往 [Releases](https://github.com/ITer99/skill-mover/releases) 下载最新版 EXE。
2. 双击运行下载的 `skill-mover-版本号.exe`。
3. 在源路径右侧选择“文件夹”或“文件”，默认为“文件夹”。
4. 点击“浏览”，选择需要分发的源文件或源文件夹。
5. 点击“添加目标”，逐个添加接收文件的目录。
6. 确认目标列表后，点击“开始搬运”。
7. 等待进度完成。

目标路径添加一次后会自动保存。下次启动程序时，目标列表会直接恢复，只需要重新选择本次要分发的源文件或源文件夹。

## 复制规则

假设源文件夹为：

```text
D:\MySkill
```

目标文件夹为：

```text
C:\Users\User\.codex\skills
\\NAS\AgentSkills
```

搬运后会生成：

```text
C:\Users\User\.codex\skills\MySkill
\\NAS\AgentSkills\MySkill
```

具体规则：

- 文件模式下，源文件会以原文件名直接复制到每个目标文件夹；
- 复制的是源文件夹本身，而不只是其中的文件；
- 源文件夹中的全部文件、空目录和子目录都会保留；
- 目标中已有的同名文件会被新文件覆盖；
- 目标中没有出现在源文件夹里的其他文件不会被删除；
- 目标路径不可用、网络中断或没有写入权限时，本次任务会提示失败；
- Git 仓库元数据和常见开发缓存默认不会分发到目标目录；
- 个别文件复制失败时，程序会继续处理其他文件，并在完成提示中列出跳过项；
- 当前版本不是双向同步工具，不会把目标目录的修改反向同步到源目录。

## 路径记忆

目标路径配置保存在：

```text
%APPDATA%\skill搬运工\config.json
```

源文件夹不会被记忆，避免下次启动后误将旧内容再次分发。

对于 SMB 路径，程序会记住路径本身，但无法保证远程终端始终在线。开始搬运前，请确保网络连接、共享服务和登录凭据均有效。

## 系统要求

- Windows 10 或 Windows 11；
- 系统已启用 .NET Framework 4.8；
- 使用 SMB 目标时，需要具备对应共享目录的访问和写入权限。

## 项目结构

- `SkillMover.cs`：Windows 原生 WinForms 源码；
- `build-native.ps1`：原生 EXE 编译脚本；
- `assets\skill搬运工.ico`：程序多尺寸图标；
- `make_icon.py`：图标生成脚本；
- `app.pyw`、`copy_engine.py`：早期 Python 版本及复制逻辑参考；
- `test_copy_engine.py`：复制与配置读写测试。

Git 仓库只保存源码、文档和构建资源。编译后的 EXE 不进入源码仓库，正式版本统一通过 [GitHub Releases](https://github.com/ITer99/skill-mover/releases) 发布。

## 重新编译

在项目目录中运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build-native.ps1
```

编译完成后，成品位于：

```text
dist\skill搬运工.exe
```

## 当前定位

“Skill”是它诞生的原因，但不是它的使用边界。

无论要分发的是一个 AI Skill、一套配置、一个项目模板，还是需要通过 SMB 送往多台终端的共享资料，`skill搬运工` 处理的都是同一件事：

> 让一份整理好的文件夹，简单、明确地到达多个目标位置。
